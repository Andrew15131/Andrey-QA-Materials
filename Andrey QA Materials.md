# Тестовая документация — чек-лист, тест-кейс, баг-репорт

Материалы подготовлены в рамках учебной практики. Названия продукта, стенды, учётные данные и роли обезличены — показана структура и качество оформления, а не привязка к конкретному проекту.

## 2. Тест-кейс: пересчёт лимита при изменении периода отчёта

**ID:** TC-PERIOD-001

**Предусловия:**

| № | Условие |
|---|---|
| 1 | Тестовый стенд доступен |
| 2 | Пользователь авторизован с ролью «Доступ к отчётам» |
| 3 | В системе присутствуют данные за периоды: текущий месяц, текущий квартал, текущий год, а также исторические данные (с 2019 года) |
| 4 | Пользователь находится на странице отчётов с панелью фильтров |

**Шаги воспроизведения:**

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть страницу отчётов | Страница загружена, фильтр периода отображается |
| 2 | Выбрать период «Текущий месяц» | Период применён (01.08–31.08.2026); лимит соответствует месячному значению (0/1000) |
| 3 | Выбрать период «Текущий квартал» | Период применён (01.07–30.09.2026); лимит должен пересчитаться на квартал (ожидаемо 0/3000, если лимит месячный ×3) |
| 4 | Выбрать период «Текущий год» | Период применён (01.01–31.12.2026); лимит должен пересчитаться на год (ожидаемо 0/12000) |
| 5 | Выбрать произвольный многолетний период | Период применён; лимит должен пересчитаться пропорционально диапазону |

**Фактический результат** (отдельная сверка, а не часть ожидания):

| Период | Лимит (факт) | Лимит (ожидаемо) |
|---|---|---|
| Месяц | 0/1000 | 0/1000 |
| Квартал | 28/1000 | 0/3000 |
| Год | 28/1000 | 0/12000 |
| Произвольный | 28/1000 | пропорционально диапазону |

Остаток на счёте (1972/2000) — глобальный показатель, не зависит от периода, поведение корректно.

## 3. Баг-репорт

**Заголовок:** Лимит на странице отчётов не пересчитывается при смене периода — остаётся фиксированным независимо от длины диапазона

**Окружение:** stage-стенд, тестовый тенант
**Пользователь:** роль «Доступ к отчётам»

**Предусловия:**
- В системе есть данные за месяц, квартал, год и произвольный многолетний диапазон

**Шаги воспроизведения:**
1. Открыть страницу отчётов, выбрать период «Текущий месяц» — зафиксировать значение лимита
2. Сменить период на «Текущий квартал»
3. Проверить значение лимита
4. Повторить для «Текущий год» и произвольного диапазона

**Фактический результат:** значение лимита (знаменатель) не меняется при смене периода — остаётся тем же, что и для месяца, независимо от выбранного диапазона.

**Ожидаемый результат:** лимит должен масштабироваться пропорционально длине выбранного периода (месяц/квартал/год/произвольный).

**Дополнительно:**
- Симптом проявляется на странице (фронт), но похоже на серверную логику — значение лимита, вероятно, приходит с backend без учёта длины периода, а не теряется при отображении.
- Для подтверждения нужна проверка через DevTools → Network: сравнить ответ API для 2–3 разных периодов и приложить endpoint + JSON-ответ.
